# Codex execution and validation protocol — VSLICE-004

1. **Baseline:** Read `AGENTS.md`, accepted ADR-001–006, VSLICE-001–003 evidence and this kit. Verify current branch, merge base, status, launcher and real source layout. Do not presume PR #11 has been merged; check. Record any conflicts with newer accepted contracts and stop to propose a bounded ADR if changes would be required.
2. **Gap analysis:** Trace the existing launcher, OpenRouter credential path, consent UI, provider request, suggestion parser, preview, approval, registry, kernel, WASM, reactive projection and persistence. Build a requirements-to-code/test mapping. Reuse ADR-006; avoid duplicate provider logic.
3. **Implementation:** Make the minimal UX/state improvements needed for full Linux live journey, including explicit remote disclosure, separate approval, progress/cancellation, typed errors and provider selection. Never change WIT/manifest/room/approval schemas merely to satisfy tests.
4. **CI tests:** Implement VS4-001–026 as real named executable integration tests, including actual Qt desktop events with an injected deterministic mock HTTP transport, genuine registry/kernel/guest execution, separate-process cold restore and output checks. Use a private sandboxed test user-data directory. Do not use external API keys in CI.
5. **Failure policy:** Test provider refusal, malformed output, unexpected fields, 401/429/5xx, timeout, cancellation, switch and no-network. Preserve prior accepted state and precise distinction between successful topology commit and subsequent ingress failure.
6. **Review A:** Have a reviewer independent from implementation inspect privacy consent, outbound request content, SSRF/egress boundaries, secret handling, metadata prompt injection, malformed suggestions, authorization and logs. Capture findings and retest resolution.
7. **Review B:** Independently review desktop state machine, accessibility, event ordering, revision fences, WASM result provenance, clean restart and recovery. Capture findings and retest resolution.
8. **Hosted:** Run full locked Rust/Qt/Python/contract/ABI/IPC/REG/UI/OP/LLM/VSLICE regression suite in GitHub-hosted Linux CI on the final implementation commit. Archive logs, versions, job URL, commit, checksums and evidence downloads. A pending rerun is not a passing run.
9. **Live:** In an opt-in local session use approved OpenRouter credentials and a declared model. Complete VS4-030 with visible consent, model suggestion, user approval, mortgage WASM output, edited result, offline restart. Record sanitized timestamps, model ID, provider count, usage/cost if available, latency and redacted error classifications. Remove all secrets from submitted evidence.
10. **Acceptance:** Complete `evidence/RESULTS.md` using the template. Verify every VS4 gate and review, and link successful hosted and live evidence. Only then change status to `ACCEPTED — Linux/OpenRouter` and describe tested model limitations. Otherwise retain PROPOSED or limited verified status.

### Prohibited shortcuts
No fixture-only acceptance for VS4-030; no fake Qt screenshots; no disabling failed gates; no hardcoded mortgage result, component digest or version; no forced approval; no silent auto-retry of plan application; no remote component installation; no secret-bearing logs; no claims for other providers or platforms.
