# ADR-002 — Component Lifecycle, Host Services and IPC Semantics

**Status:** PROPOSED — acceptance pending executable validation
**Version:** 0.1 · 2026-10-15
**Decision owners:** Kernel, WASM host, bus, reactive engine, persistence and verification maintainers
**Related:** Accepted ADR-001; Architecture and Interface Specification v0.1 §§4–8, 12–14; Component Package and Manifest Specification v0.1; ADR-003 (Qt bridge), capability-policy ADR, storage ADR

## 1. Context and constraints

ADR-001 accepts Wasmtime 49.0.1, `workbench:component@0.1.0` and the synchronous, pure `compute(message) -> result<list<message>, component-error>` world. The validation spike exercised ABI checks, guest isolation, errors, schemas and resource budgets. It did **not** implement a production kernel, persistent instances, a bus or privileged host imports. This decision supplies those missing **host-side** semantics without modifying accepted WIT.

Architecture v0.1 requires a process-local bus, per-source deterministic order, monotonic room-local sequence, bounded queues, typed validation, a DAG reactive scheduler, optimistic room revisions and explicit/auditable lifecycle transitions. Component packaging distinguishes **artifact lifecycle** from **instance lifecycle**. No Operator invocation is permitted in the ordinary reactive update loop.

## 2. Decision summary

1. **Keep ADR-001 ABI unchanged.** A v0.1 pure computation guest imports no Workbench or WASI services. Host services are APIs *inside the trusted Rust process*, not implicit guest imports. A privileged guest world would require a new, separately versioned WIT world and ADR.
2. **Use typed Rust structures within one process.** Canonical versioned JSON envelopes are the portable inspection/fixture representation. Do not introduce Protobuf/FlatBuffers into the v0.1 runtime path absent measured need. A future transport codec must preserve envelope semantics.
3. **The kernel owns lifecycle and identity.** Installed packages are immutable; room-scoped instance identifiers are unique. One logical instance has a designated Wasmtime execution isolation boundary; initial implementation uses a fresh `Store` per compute invocation consistent with the validated ADR-001 host, retaining logical identity/state in the host. A guest's memory is never a persistence mechanism.
4. **Per-room serialized control plane.** Topology changes, user input commits, cancellation and lifecycle commands receive deterministic room sequence numbers. Computation may run concurrently across rooms; v0.1 uses deterministic topological execution *within a room* (sequential initial scheduler).
5. **At-most-once attempt, no implicit retry.** Bus delivery is best described as accepted-and-processed or explicit failure. No exactly-once execution claims. Pure invocations can be retried only by an explicit scheduler policy as a new attempt with its own identity; v0.1 defaults to no retry.
6. **Bounded, reject-on-full queues.** Backpressure is surfaced as a typed `QUEUE_FULL` failure; the scheduler must not silently drop committed state updates. Optional coalescing is confined to uncommitted superseded UI input events, never committed revisions, lifecycle events, permission decisions or errors.
7. **Atomic topology application with revision checking.** Validate plans and authorizations before commit; stale `expectedRoomRevision` returns `STATE_CONFLICT` without topology mutation. Newly reserved resources must be released on failure.
8. **Error propagation is structured.** Validation errors, reported guest errors, traps, budgets, cancellations and downstream suppression remain distinguishable and correlated; a failed output batch is never partly committed.

## 3. Terminology and authority

- **Package:** immutable installed artifact keyed by `{componentId, version, sha256}`; governed by package specification and registry. Installing is not starting.
- **Logical instance:** room-owned component instance keyed by `{roomId, instanceId}` referencing a pinned package. It includes connections, configuration, current host-owned input/output projections and lifecycle status.
- **Invocation:** one execution attempt against a coherent input snapshot; has `invocationId`, `roomRevision`, correlation and resource budgets.
- **Host service:** trusted Rust API (registry lookup, instance management, validation, routing, state commits, capabilities, diagnostics). No component may directly call it through the pure WIT world.
- **Control event:** lifecycle/topology/capability command, distinct from a data event and handled on the room control path.
- **Data event:** typed port update accepted by the host; the guest emits candidate outputs, not authorized bus events.

## 4. Ownership and module boundaries

| Subsystem | Owns | Must not own |
|---|---|---|
| `wb-kernel` | room controller, instance state transitions, orchestration, dispatch authorization | graph semantics, UI rendering, guest-supplied permissions |
| `wb-wasm-host` | component validation/instantiation, per-call Stores, ABI invocation, limits, trap classification | room revision, routing, persistence transactions |
| `wb-bus` | envelopes, routing rules, bounded queues, ordering/correlation metadata | authorization decisions, LLM involvement, module code execution |
| `wb-reactive` | DAG topology, dirty-set computation, topological scheduling, stale-result checks | direct filesystem access, agent decisions |
| `wb-contracts` | versioned DTOs and stable errors | runtime side effects |
| `wb-capabilities` | host policy/grants and revocation | deriving grants from RDF claims |
| `wb-storage` | durable snapshots/event records and revision CAS | opaque runtime authority |
| `wb-registry` | validated immutable artifacts and pin resolution | running code during discovery |
| Qt bridge (future ADR-003) | UI projection, event forwarding | mutable authoritative state |

The orchestration layer **must not** allow modules to bypass the runtime-host entry point or the capability authority.

## 5. Artifact and instance lifecycle

### 5.1 Artifact lifecycle (registry-owned)

`discovered -> validated -> installed`; on error `rejected`. `validated` means schema, path, digest, RDF consistency and ABI admission checks pass as independently specified; it never means trusted or authorized. Removal rules preserve pinned-room recoverability.

### 5.2 Instance lifecycle (kernel-owned)

Initial states: `declared`, `prepared`, `running`, `stopped`, `failed`.

| From | Command/event | To | Rule |
|---|---|---|---|
| absent | apply committed topology | declared | pinned package resolvable, ID unique |
| declared | prepare | prepared | verify pinned digest, grants, quotas and compatible ABI |
| prepared | start | running | publish start lifecycle event |
| running | stop | stopped | no new invocation; drain or cancel bounded in-flight work |
| prepared/running | trap or unrecoverable host failure | failed | record error, invalidate dependent outputs |
| declared/prepared/running/stopped | remove via committed topology | absent | stop/cancel first, remove edges, release resources |
| stopped/failed | explicit prepare/restart | prepared | re-run admission and capability checks; no implicit privilege inheritance |

`prepare` may fail without entering `running` and must record a structured reason. Guest code is not executed during discovery, validation or installation. State transitions must be audited with room revision, actor, instance and correlation ID. A restart creates a new execution generation so late prior results cannot be applied. For v0.1, snapshotting persistent guest memory and suspend/resume are **not supported**.

### 5.3 Cancellation

A stop/replacement invalidates the current execution generation. The kernel requests cancellation; the host enforces a resource/epoch limit. Late results from cancelled generations are discarded as `STALE_RESULT`. Stop is complete only once resources are released or the host has isolated and rendered the abandoned execution incapable of committing results.

## 6. IPC envelope and routing

The **Architecture v0.1 canonical envelope** remains authoritative, including `protocolVersion`, `messageId`, `roomId`, `source`, `destination`, `correlationId`, `sequence`, `schemaId`, `payload`. Additional internal metadata is held in trusted Rust structs, not injected into guest payloads:

```json
{
  "protocolVersion": "0.1",
  "messageId": "0189e5cb-0e59-7b20-b5fb-c3ff12345678",
  "roomId": "room-local-001",
  "source": {"instanceId": "mortgage-1", "port": "payment"},
  "destination": {"instanceId": "canvas-1", "port": "monthlyPayment"},
  "correlationId": "0189e5cb-0e59-7b20-b5fb-c3ff12345678",
  "sequence": 12,
  "schemaId": "org.workbench.example.mortgage-payment@0.1",
  "payload": {"monthlyPayment": "1432.25", "currency": "GBP"}
}
```

- The host, **not the guest**, creates `messageId`, assigns monotonic per-room `sequence`, authorizes destination edges and sets source provenance.
- A guest `message.port` names only an output port and `payload-json` holds a JSON string. It cannot forge canonical envelope routing fields or select an arbitrary target instance.
- `protocolVersion=0.1` is the only supported version for v0.1; unknown versions fail `UNSUPPORTED_VERSION`.
- Port schemas are validated *at ingress and before downstream delivery*. Semantic/unit compatibility is checked when edges are committed. No lossy implicit conversion.
- The bus accepts only messages from known running instances or authorized UI/host input adapters; no cross-room edges in v0.1.
- `correlationId` links an input and its resulting emissions/errors. Room-local sequence orders **accepted events**, not physical wall-clock execution or delivery across different rooms.
- Source output batches are validated as a whole; a single invalid output aborts the batch and preserves previously committed state.

### 6.1 Public DTO sketch (not a replacement for contract schemas)

```rust
struct Endpoint { instance_id: String, port: String }
struct EventEnvelope {
    protocol_version: String,
    message_id: String,
    room_id: String,
    source: Endpoint,
    destination: Endpoint,
    correlation_id: String,
    sequence: u64,
    schema_id: String,
    payload: serde_json::Value,
}
struct DispatchContext {
    room_revision: u64,
    execution_generation: u64,
    invocation_id: String,
}
```

Serialize with the canonical JSON key spelling from the architecture; `DispatchContext` stays host-internal. A central allocation step is responsible for unique sequence numbers. Duplicate message IDs are rejected at ingress. No distributed deduplication guarantees are implied.

## 7. Scheduling and reactive semantics

1. Topology is a validated directed acyclic graph. Cycles yield `CYCLIC_DEPENDENCY` before commit.
2. Each input change becomes one accepted room revision; the scheduler freezes a coherent snapshot of upstream values for each affected compute invocation.
3. Dirty descendants are scheduled in stable topological order, ties broken by **lexicographically ascending `instanceId`**; no reliance on hash-map iteration order.
4. Each invocation receives one input message as required by ADR-001; where multiple inputs change, a deterministic host adaptation policy is needed per component/port. **For v0.1, multi-input atomic snapshot execution is out of scope** unless the component declares one aggregate input port. This avoids inventing batch WIT semantics.
5. For any result to commit, both room revision and execution generation must still match expected values. Otherwise return `STALE_RESULT`; never overwrite more recent committed input.
6. Derived outputs are validated and committed atomically as one batch against room state; only then are downstream nodes activated. Invalid output suppresses that batch and propagates a structured error state to affected dependent projections.
7. An Operator/LLM is never invoked as part of a normal data propagation loop.
8. Fixed scheduling order does not imply deterministic guest code; reproducible outputs depend on pure guest behavior and pinned artifacts.

## 8. Backpressure, delivery and limits

- Start with **per-room queues**, explicit finite capacity (proposed default: 256 pending data/control events combined). This is an initial engineering parameter, **not** a product security limit and must be tested/adjusted.
- Use **reject-new** (`QUEUE_FULL`) once at capacity. Never silently drop a committed input update. A caller may retry explicitly after observing failure, with a new message identity.
- Reserve control-command capacity separately in the implementation or ensure stop/cancel/close cannot be starved by data volume. The exact reserve and queue technology are implementation details; acceptance test `IPC-009` must demonstrate liveness under saturation.
- Preserve acceptance ordering per room; for independent sources their order is the order the kernel serializes acceptance, not wall-clock arrival.
- No promises of exactly-once guest side effects, durable queue replay, network distribution or delivery after crash.
- Respect ADR-001 spike ceilings where the existing Wasmtime host applies them, but treat them as **test budgets**, not globally adopted production thresholds; future per-component limits require a resource policy ADR.

## 9. Host services and permission boundary

Trusted services exposed through Rust traits (example signatures are illustrative):

```rust
trait HostServices {
    fn resolve_pinned(&self, id: &str, version: &str, sha256: &str)
        -> Result<ResolvedArtifact, HostError>;
    fn authorize(&self, instance: &InstanceKey, request: &CapabilityRequest)
        -> Result<Grant, HostError>;
    fn dispatch(&self, event: EventEnvelope) -> Result<(), HostError>;
    fn commit_room(&self, change: RoomMutation, expected_revision: u64)
        -> Result<u64, HostError>;
    fn record_event(&self, event: AuditEvent) -> Result<(), HostError>;
}
```

This trait is a **responsibility sketch**, not a frozen public Rust API. Privileges are checked at the time of use; an installed package's manifest is a declaration of required permissions, not a grant. Grants are instance-/operation-/resource-scoped, revocable and re-evaluated on room restoration. The pure WIT world has no host imports; filesystem/network/build tools need later separately approved capability world(s), not custom JSON escape hatches. Neither RDF metadata nor guest outputs grant new authority.

## 10. Atomicity, failure and recovery

- Composition plan application is an optimistic revision-checked transaction. Stage validation, registry pin lookup, graph checking, permission prompts and resource reservation before commit. Do not publish partially applied edges or instances.
- On plan failure, restore prior topology and release reservations. Whether durable storage and volatile topology use one physical transaction is subject to the storage ADR; the externally visible guarantee is no partial committed topology.
- On guest `component-error`, return `GUEST_ERROR` with the component's code/detail; on trap/budget, return `COMPONENT_TRAP` or `RESOURCE_LIMIT` with correlated error details. Preserve existing architecture error names where already specified; additions in this ADR (`QUEUE_FULL`, `STALE_RESULT`, `GUEST_ERROR`, `RESOURCE_LIMIT`, `CANCELLED`) must be added to the shared error registry before implementation.
- Never treat a `result::err` as valid component output. On a trap, mark the instance `failed`, quarantine its execution generation, report to room state, and do not crash unrelated rooms/instances.
- Restart is explicit and revalidates admission. No implicit retry or automatic LLM recovery.
- Room restart/restore uses pinned package identities and persisted host-owned state, validates it, constructs new execution generations, and recomputes derived outputs. In-flight queues, Wasmtime `Store`s and capability grant tokens are **not** persisted.
- Persistence durability/atomicity of event logs remains governed by storage ADR; this ADR does not promise crash-safe exactly-once dispatch.

## 11. Observability

Emit structured events for `instance.declared`, `prepared`, `started`, `stopped`, `failed`, `removed`, `room.revised`, `dispatch.accepted`, `dispatch.rejected`, `invocation.started`, `invocation.completed`, `invocation.failed` and `backpressure.rejected`. Include IDs, revisions, timing and error code. Avoid payload logging by default; apply redaction to secrets and user data. Separate user-visible errors from diagnostic data.

## 12. Alternatives considered

| Alternative | Benefits | Why not selected for v0.1 |
|---|---|---|
| Protobuf/FlatBuffers everywhere | Efficient typed wire encoding | Adds generation/versioning before process-local performance need is shown |
| In-memory actor per WASM guest | Natural mailbox/stateful model | Conflicts with intentionally pure stateless ADR-001 world; grows lifecycle complexity |
| Persist and replay all bus events | Durable replay | Requires transactionally coupled storage and side-effect policy not designed yet |
| Guest-managed direct peer IPC | Low host overhead | Breaks authorization and schema enforcement boundary |
| Concurrent arbitrary DAG scheduling | Throughput | Nontrivial deterministic merge, stale-result and cancellation behavior |
| Automatic guest retries | Convenience | Can obscure errors and creates risk for future side-effecting worlds |

## 13. Consequences

**Advantages:** clear ownership, testable deterministic local semantics, no WIT breakage, structured failures, bounded memory exposure on queues, room isolation, portable serialization fixtures, and a tractable integration path to reactive state and UI.

**Costs:** process-local serial ordering may cap throughput; copying JSON has overhead; guest state is host-owned; no streaming/async services; initial multi-input handling requires aggregate input ports; persisting large event histories or distributed operation will need later ADRs.

## 15. Acceptance gates and follow-ups

**PROPOSED → ACCEPTED only when:** IPC-001–015 pass with reproducible hosted Linux evidence; reviewers confirm no changes to accepted WIT, schema or ontology without their own ADR; the runtime integration and queue semantics are covered by executable tests. A design-only review is not acceptance.

**Immediately implementable:** `wb-contracts` DTOs and errors, `wb-bus` in-memory queue/router, `wb-kernel` logical lifecycle, `wb-reactive` DAG scheduler fixtures, a host adapter around the ADR-001 spike, with integration tests.

**Not authorized by ADR-002:** adding WASI imports, arbitrary native plugins, switching WIT world, persistence engine choice, Qt FFI mechanism, production security budget approval, unsigned network registry, cross-process IPC or distributed guarantees.

**Future work:** stateful/privileged component worlds; storage transaction ADR; capability vocabulary; Qt bridge; queue metrics/benchmarks; coalescing policy; multi-input scheduling; streaming support.

## 16. Executable validation profile

The implementation is additive: legacy bootstrap DTO/check helpers remain for
compatibility, while the canonical EventEnvelope and shared error registry live
in wb-contracts::ipc. Stable validation additions INVALID_TRANSITION, DUPLICATE_ID
and INVALID_ENVELOPE distinguish lifecycle/identity/shape failures. No existing
schema, ontology, accepted WIT, ABI fixture or host execution implementation changes.

`dispatch.accepted` acknowledges a validated pending event, not an authoritative
input commit. UI events remain uncommitted in a finite FIFO until the scheduler
starts a wave; `room.revised` marks that input's one revision commit. The wave
finishes derived work in stable graph order before committing the next UI event.
This preserves committed inputs and per-source order without coalescing or retries.
Lifecycle prepare/start/stop use the control sequence and execution generations;
they do not independently increment input/topology revisions. Explicit topology
CAS still invalidates detached work by the exact revision fence.

One aggregate input port per instance and one upstream producer per connected
input are the initial adaptation profile. Structural schema documents, explicit
semantic types and units must match exactly; generalized compatibility remains
ADR-005. Duplicate output port entries in one candidate batch are rejected as
ambiguous rather than silently selecting one. Queue-full fanout aborts the whole
output transaction. All such failures remain structured and correlated.

Stop revokes active commit authority across the whole descendant set, not only
the stopped instance. A detached worker uses the unchanged ADR-001 resource/epoch
ceilings; it cannot access room state or commit after cancellation. Invocation
leases bound outstanding/quarantined tickets independently of logical instances.
Default execution policy is deny; native approvals explicitly name room, instance
and exact pin. They approve pure execution only and are not capability grants.

Logical snapshots store authoritative aggregate input values as instance.port.
Derived values are recomputed and cannot overwrite an input with the same port
name. Restore constructs newly admitted running generations, checks current policy,
and re-enqueues root inputs; it never revives persisted memory, queues, UI adapters
or grants. Whole-port addressing is this spike's profile; field-level migration
and durable sequencing across process restart remain ADR-004 work. Sequence clocks
are retained per live Kernel/room, including in-process restore.

The bundle cache consumes trusted resolver inputs and additionally checks canonical
manifest, bytes/digest, schema and ABI. It is not a production registry installer or
RDF verifier. Queue capacity bounds pending data, not all native allocations;
deduplication and audit history persist for the controller lifetime. Production
retention policy and original compiler/schema/native-lifting budgets remain separate.

Independent review and named IPC results are recorded in
[evidence/ADR-002-results.md](evidence/ADR-002-results.md). A passing local IPC-015
declaration test is not hosted acceptance: the actual workflow conclusion and
artifacts must be verified before changing Proposed status.
