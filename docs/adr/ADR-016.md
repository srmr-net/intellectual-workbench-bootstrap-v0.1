# ADR-016 — Host-only conversational Operator presentation

Status: Proposed. User-authorized implementation scope, 2026-10-29. Does not supersede ADR006 or grant conversational output any execution authority.

The user rejected the tool-request-first flow and explicitly requested a normal long-running conversation with real OpenRouter contextual chat. ADR006 deliberately excludes broad chat memory: its structured suggestion adapter cannot truthfully serve as a conversational backend. Introduce a separate host-only text conversation adapter and `chat.1` process protocol, with no registry/kernel/room handle. Reuse the accepted fixed-origin HTTPS transport and credential policy source byte-for-byte. Existing structured suggestion, exact pin, preview and approval remain the only tool execution route.

Qt renders response text as inert text; no model markup, links, QML, shell commands, tools or executable plans are interpreted. Host owns system message, roles, history, routing, credentials and quotas. Only complete user/assistant pairs from the selected chat become bounded context; failed/cancelled turns and other chats are excluded. Initial history is process-local, not stored in room snapshots. Context trimming is disclosed; it does not erase the visible transcript.

Remote is disabled until session enablement in Settings. Disclosure covers current message plus bounded recent conversation, fixed OpenRouter/NVIDIA destination/model, free-provider logging, no tool/registry/room data, no automatic retries and limits. Each Send is one request. Cancellation/switch/disable/quit drops and reaps active transport and fences pending responses. No startup, restore or ordinary canvas action sends a conversation request.

New protocol operations: configure(enabled, credentialPath), new, select(sessionId), send(sessionId,text), cancel and quit. Host assigns opaque session/turn IDs, validates strict bounded frames, returns state/start/result/error events, and retains bounded private in-memory transcript/context. Secrets are never serialized to Qt. Native errors contain only typed codes and safe metrics; content is sent only as explicit conversation display data, never diagnostic logs.

Alternatives rejected: treating tool JSON as general chat; passing full transcript as user-controlled roles; allowing freeform chat to apply topology; arbitrary endpoint/model fallback; using room snapshots for chat; adding model tools or a generic shell agent. Streaming tokens and durable chat storage are deferred; asynchronous progress/cancellation are implemented first. Accepted runtime contracts and review requirements remain binding. Acceptance requires deterministic native/Qt tests, independent review and documented real chat validation; Proposed is not production acceptance.
