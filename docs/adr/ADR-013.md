# ADR-013 — Committed desktop checkpoints and internal host coordination

Status: Accepted — 2026-10-27, scoped VSLICE-002 Linux profile.
Evidence: [24 gates, independent reviews and verified hosted artifacts](../implementation/vslice-002/evidence/RESULTS.md).
Dependencies: accepted ADR001–004 and VSLICE001. ADR012 database recovery remains open.

## Context

The accepted logical RoomSnapshot saves inputs and recomputes derived outputs.
VSLICE002 requires cold-process display of the last coherent committed canvas with
zero guest/model execution merely to render it. It also requires installed-only
selection, pinning, private durable state and explicit non-destructive recovery.

## Decision

A separate trusted desktop coordinator stores an internal format1 workspace:
stable room/instance identity, exact component/version/artifact pin, UI path/raw/
schema digests, pin flag, selected canvas, logical input snapshot and the last
successful complete output map. No widget code, draft, grant or guest memory is
persisted. Every room/pin/UI and authoritative aggregate schema is verified before
any saved view is materialized. Saved output is a durable committed display cache;
it is never injected as newly authoritative kernel output.

Only a later complete valid edit activates a fresh explicitly approved pure kernel
incarnation. It uses accepted Room/Kernel APIs and real typed ingress/WASM/atomic
output validation. Any required restore recomputation is suppressed from the view.
Desktop selection epochs and durable revisions are checked before mapping to fresh
native authority; no client stale counter is promoted silently. Failed invocations
retain the prior coherent durable pair and correlated diagnostics. Valid native
commits alone replace that pair.

The internal desktop.1 transport adds typed selection/pin/quit coordination, with
1MiB frames,32 bounded incoming/outgoing events, finite metadata/room/control limits
and bounded trace/live audit retention. It does not replace accepted UI, IPC or WIT
protocols. The byte-preserved generic renderer is embedded by trusted native Qt;
only literal data from admitted metadata selects its fixed controls.

The storage adapter holds a private anchored directory and exclusive writer lock.
Strict duplicate-safe JSON, closed versioned schema, canonical content checksum,
size/identity limits, no-follow regular single-link reads, CAS, unique private temp,
file sync, atomic rename and directory sync apply. Every acknowledged state/pin/
selection transition is saved before ACK. Clean quit drains accepted work and
flushes its final reply asynchronously. Corrupt/incompatible/missing pins or storage
failure latch read-only recovery, preserving diagnostic bytes without substitution.

## Limits

This is single-writer clean-quit persistence, not a database engine, transaction
replay or physical power-loss proof. The checksum detects accidental corruption;
it does not authenticate against a malicious trusted host UID. Cross-store deletion
is reconciled deterministically as missing-pin recovery, not a multi-store atomic
transaction. There is no automatic migration/import of old headless snapshots.
One exact UI component instance per room and the accepted restricted UI vocabulary
are supported. Richer canvas graphs, cross-platform packaging and platform screen
reader certification remain future work. No Operator, remote store, WASI permission
or privileged guest service is introduced.
