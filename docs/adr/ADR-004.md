# ADR-004 — Semantic UI Rendering and Host Integration

**Status:** PROPOSED — executable validation, independent reviews and hosted Linux CI required
**Version:** 0.1 · 2026-10-26
**Owners:** desktop Qt, kernel, contracts, reactive, registry, semantic, security, verification
**Dependencies:** Accepted ADR-001, ADR-002, ADR-003 and VSLICE-001; architecture, ontology and Component Package/Manifest v0.1.
**Purpose:** establish the first **declarative, trusted, reactive native presentation path** without involving Operator or changing the accepted guest ABI.

## 1. Context and design constraints

The accepted headless mortgage slice already exercises signed-off registry admission of pure-WASM packages, exact pinning, host lifecycle, deterministic bus processing and validated state commits. The original application design requires a multi-platform canvas rendered from abstract, semantic UI metadata; the initial host is Qt/QML. The bootstrap mortgage `ui.json` is **illustrative, not a normative validated schema** and uses example binding paths that must be reconciled with the *actual* accepted mortgage input/output ports. ADR-003 excludes UI-bearing packages in its accepted v0.1 scope. This ADR specifies a **new, separately gated extension**, not a claim that those packages are already admitted.

### Required invariant

Untrusted package metadata may *describe* interface controls; only trusted host code constructs QML objects. The view can request typed input changes but cannot forge bus provenance, bypass capabilities or mutate committed room state directly. Reactive changes do not invoke Operator or an LLM.

## 2. Decision summary (normative)

1. **Keep ADR-001 WIT and ADR-002 execution semantics unchanged.** `compute(message)` remains the sole v0.1 guest entrypoint. UI is host-owned; components have no QML/Qt imports.
2. **Introduce semantic UI document `uiVersion: "0.1"`** governed by a committed JSON Schema; no QML, JS, HTML, arbitrary expressions, script URLs, embedded code or remote UI references. UI references stay inside an admitted package. Unknown fields/types/versions fail closed.
3. **Qt Quick/QML remains trusted presentation implementation.** Use a small set of reviewed QML primitives; never evaluate supplied QML source, dynamically import package code, or bind arbitrary property names supplied by the component.
4. **Bridge Rust↔Qt via an explicit asynchronous adapter**, with Qt objects and signals owned and accessed only on the GUI thread. A concrete bridge library (CXX-Qt, QObject/C ABI, etc.) is an implementation choice resolved by a documented spike; exported semantic messages are independent of that choice.
5. **Bindings are declarative, typed and explicit.** Every editable control maps to an authorised host ingress field on a declared component input port; every readout maps to an accepted committed output projection. Binding direction is fixed by control class. Package-supplied strings are never executed as expressions.
6. **Use a host-owned draft/edit buffer distinct from committed room state.** Validation failures and unfinished edits never mutate authoritative state. Input acceptance goes through the existing ADR-002 room controller with expected revision/generation; results update the view only after an accepted state commit.
7. **Change delivery is bounded and revision-aware.** The bridge consumes immutable UI projections keyed by room, instance, revision and execution generation; stale/out-of-order projections cannot overwrite a newer view. UI events are queued with bounded capacity; overload returns a visible typed error, not silent loss.
8. **Extend local registry admission narrowly.** UI-bearing packages are enabled only after their `ui.json` validates, paths are safe, bindings reconcile with the authoritative `component.json` ports and input/output schemas, and RDF references agree. No new package format, remote store, permission grant or mutable upgrade.
9. **Restoration renders the pinned, validated interface and last committed values.** A room with a missing/unavailable/mismatched component or UI package fails safely and visibly; no implicit upgrade or Operator reconstruction.
10. **Presentation accessibility and deterministic tests are acceptance criteria.** Labels, reading order, keyboard access, error feedback, screen-reader semantics, focus preservation and theme/scale behaviour are part of v0.1, not polish deferred indefinitely.

## 3. Explicit scope

**In:** deterministic form renderer, `decimal-input`, `integer-input`, `readout`, `form`, display labels/units, typed bindings, Qt↔Rust message boundary, a mortgage screen driven by installed metadata, room restore, headless UI-contract tests, offscreen Qt smoke tests.
**Out:** Operator, arbitrary layouts/charts, generated QML, UI plugins supplying executable controls, WASI imports, cross-room UI writes, collaboration, mobile/web renderers, network component registries, embedded JavaScript expressions, remote asset loading.

## 4. Ownership and trust boundaries

| Subsystem | Owns | MUST NOT do |
|---|---|---|
| `wb-contracts` | UI schema DTOs/versioned validation errors and projection/event DTOs | Render controls, confer permissions |
| `wb-registry` | UI file admission, path/digest/file-reference checks, immutable verified UI handle | Evaluate UI, execute guest during admission |
| `wb-semantic` | UI-to-manifest/RDF reconciliation; semantic labels/units | Authorize arbitrary bindings or code |
| `wb-kernel` / `wb-reactive` | Authoritative room state, ingress, revision checks, execution and committed output projections | Accept direct QML mutations as committed state |
| `wb-capabilities` | Capability policy, including input permissions where applicable | Treat UI existence as permission |
| `apps/desktop-qt` | GUI thread, view model, trusted QML controls, accessibility | Receive unchecked WASM bytes, execute package QML |
| UI bridge | Finite typed commands/projections, queue bounds, generation fences | Trust client-originated message IDs/room ownership |

The bridge is an authority boundary even when both sides run in one desktop process. Rust validates room/instance ownership, field name, expected revision, schema and capability grants; UI labels are **not** authorization identifiers.

## 5. Semantic UI document v0.1

### 5.1 Document shape

The pinned `ui.schema.json` in this kit is a **proposed contract**; once accepted it SHALL be copied to the repository's canonical `schemas/ui.schema.json` and versioned there. The schema is intentionally restricted to one form with an ordered sequence of controls.

```json
{
  "uiVersion": "0.1",
  "root": {
    "type": "form",
    "title": "Mortgage calculator",
    "children": [
      {"type": "decimal-input", "id": "principal", "label": "Principal", "unit": "GBP", "bind": {"direction": "input", "port": "loan", "field": "/principal"}},
      {"type": "decimal-input", "id": "rate", "label": "Annual rate", "unit": "percent", "bind": {"direction": "input", "port": "loan", "field": "/annual_rate_percent"}},
      {"type": "integer-input", "id": "term", "label": "Term (months)", "bind": {"direction": "input", "port": "loan", "field": "/term_months"}},
      {"type": "readout", "id": "payment", "label": "Monthly payment", "bind": {"direction": "output", "port": "payment", "field": "/monthly_payment"}}
    ]
  }
}
```

The shown port names are a **reference illustration**; agents MUST reconcile names and field pointers with the accepted real VSLICE-001 package before preparing its UI fixture. Changing the accepted component port contract to fit this example is prohibited. A top-level form can have 1–32 controls, each with a unique stable ID. JSON Pointer `field` is restricted to a single first-level property in v0.1 (e.g. `/principal`); use RFC 6901 escaping, prohibit arbitrary nesting, indexes and prototype/property traversal. Ports are named by the accepted manifest, not inferred from labels.

### 5.2 Schema and semantic reconciliation

- Parse UTF-8 JSON **rejecting duplicate object keys**; validate schema with `additionalProperties: false` throughout.
- Require a single referenced UI file under the admitted package; reject symlinks, links, network references, absolute paths and escaped paths using ADR-003 staging rules.
- `bind.port` MUST identify a declared manifest port of the required direction; `bind.field` MUST exist in that port's local input/output JSON Schema; derived type must match control kind: `decimal-input` is a canonical decimal string, `integer-input` an integer, `readout` read-only scalar (initially string or integer).
- Require fields used for calculation to be supported by the authoritative JSON Schema; enforce full input-object validation before dispatch (individual field edits may be incomplete).
- All UI-present RDF references must match manifest reference and declared abstract interface identity. Do not silently add or modify ontology terms; document any semantic vocabulary gap and require a reviewed mapping.
- Reject executable content even if JSON Schema permits it via a hypothetical future extension. Renderer supports a fixed set of whitelisted control kinds only.
- Numerical `unit` strings are **presentation hints**, never automatic conversions or permission claims; semantic compatibility comes from the accepted component metadata.

### 5.3 Canonicalisation and versioning

The **raw committed UI bytes** and their package membership are integrity protected by accepted immutable registry rules. UI rendering must not depend on arbitrary JSON property order. A new vocabulary requires a new `uiVersion` or additive reviewed contract; unknown versions fail `UNSUPPORTED_UI_VERSION`. Error codes MUST be stable and documented.

## 6. Rust ↔ Qt bridge contract

The transport may use a QObject-backed Rust model or a bounded typed queue with explicit GUI-thread marshalling. The DTO semantics are fixed independently of transport. Equivalent Rust types:

```rust
struct UiKey { room_id: String, instance_id: String, ui_id: String }
struct UiProjection {
    key: UiKey,
    room_revision: u64,
    execution_generation: u64,
    values: serde_json::Value, // validated committed read model only
    diagnostics: Vec<UiDiagnostic>,
}
struct UiEdit {
    key: UiKey,
    control_id: String,
    proposed_value: serde_json::Value,
    expected_room_revision: u64,
    expected_generation: u64,
    correlation_id: String, // host allocates canonical correlation/sequence
}
```

The QML layer may supply a local edit token but **never** the canonical bus message ID or route. The bridge maps control ID to a prevalidated binding table, checks room ownership/current generation and submits the resulting full or partial draft to host ingress. Successful committed writes are projected back; Qt must not assume its tentative value is authoritative. All Qt property/signal interaction occurs on the GUI thread; heavy Rust work runs off that thread. All pending callbacks are invalidated on view destruction and room switch.

### 6.1 Draft-to-commit rules

An edit first updates a host-controlled draft copy (or remains local to an authorised UI adapter), then passes type and full-object JSON validation before being sent to ADR-002. Reject invalid input with a visible diagnostic; do not invoke WASM or advance room revision. For accepted edit: emit host input with expected revision, let ADR-002 process and commit; publish revision-tagged projections to the renderer. On `STATE_CONFLICT`, refresh the projection and retain or discard user draft according to an explicit tested policy (initial recommendation: preserve draft and ask the user to apply again). Host ordering, no implicit retries, cancellation and atomic output batches remain ADR-002's rules.

### 6.2 Resource policy

Limit UI size and depth (one root + up to 32 controls in v0.1), text lengths, validation time, bridge queued events and pending operations. UI event queue default recommendation: 128 entries per room, reject-on-full; make configurable and test exact policy. Coalesce only uncommitted superseded edit drafts, never lifecycle, permission or committed projection events. UI redraws SHOULD be coalesced without losing revision/generation ordering.

## 7. Rendering and accessibility

The renderer SHALL use trusted, statically reviewed Qt Quick controls and layout construction; no dynamic QML code from package strings. Supported controls initially: form, decimal and integer input, readout. Use locale-aware display formatting only; committed decimal strings and input payloads remain canonical and locale-independent. Validate and normalise before host ingress. Every control has an associated visible accessible label and appropriate role; tab order follows semantic document order. Invalid input is exposed through visible text and accessible description. Test keyboard-only operation, large-text scaling, light/dark appearance and focus preservation under reactive readout updates. Keep QML render logic generic: no `mortgage`-specific switch on package ID or hard-coded input names.

## 8. Registry scope extension and migration

ADR-003 remains **Accepted for pure UI-free packages**. ADR-004 acceptance SHALL include a dedicated extension test demonstrating UI-bearing package admission behind a feature gate or newly versioned admission policy; it cannot retroactively claim REG tests covered this. Admission MUST require schema validity, binding-to-port reconciliation, RDF/manifest consistency, content integrity, and frozen file references. Explicitly test that an old headless package still installs and executes unchanged. If existing immutable package records lack a UI descriptor, treat it as `None` rather than synthesising UI; do not rewrite a release or silently update room pins. A UI-bearing mortgage fixture may require building a **new immutable release version or package identity**; never replace an existing pinned release with different bytes.

## 9. Failure behaviour and restore

- Invalid UI / unknown kind / bad binding → reject at admission before registry visibility.
- Invalid user edit → diagnostic, no room write or compute.
- Host `QUEUE_FULL` → surfaced and retry offered only as explicit user action.
- Stale projection / room switch / cancelled generation → discard old update; preserve current view state.
- Trap or output schema error → keep last good committed projection, show correlated failure; never show partial output as committed.
- Missing pinned UI/component on restore → explicit unavailable state, no substitution or silent download.
- View teardown or application quit → cancel/detach bridge subscriptions without use-after-free, leak or cross-room display.

## 10. Compatibility / no-change guarantees

Accepted WIT `workbench:component@0.1.0`, ADR-002 envelope/ordering/lifecycle/revision model, ADR-003 immutable exact pin semantics and existing headless VSLICE-001 result must remain unchanged. This ADR defines **new host/UI interfaces**, not new WASM guest imports. No privileged WASI, arbitrary QML, remote registry, Operator involvement or floating component version selection.

## 11. Implementation sequence

1. `UI-001`: freeze proposed schema, strict parsing, field/type-binding cross-check with real manifest and test fixtures.
2. `UI-002`: implement generic renderer and Qt↔Rust typed projection/event adapter; establish GUI thread ownership.
3. `UI-003`: connect input drafts to accepted reactive room ingress and committed projection subscriptions with revision/generation fencing.
4. `UI-004`: add separately gated registry admission for declarative UI, with immutable new mortgage package fixture.
5. `UI-005`: demonstrate mortgage calculator visually through the generic renderer, with real installed bytes, not a hard-coded calculator form.
6. `UI-006`: restore pinned UI and values and run offscreen CI and independent review.

Where necessary, run UI-001 and a narrow Qt bridge feasibility spike first; record any CXX-Qt/toolchain licensing/packaging choice in a short implementation note. Do not redesign the accepted runtime to accommodate the GUI.

## 12. Acceptance and evidence

All `UI-001` through `UI-020` tests in `TEST_MATRIX.md` MUST pass locally and on an appropriately configured GitHub-hosted Linux CI runner, including a genuine Qt offscreen instance (`QT_QPA_PLATFORM=offscreen`) or `xvfb-run` where required, with documented limitations. Mandatory tests cannot be ignored, mocked or skipped as substitutes for product-level integration. Maintain all ABI/IPC/REG/VSLICE-001 regressions. Two independent reviews: (a) Qt threading/accessibility/UI trust; (b) admission-to-state consistency, revision fencing and restoration. Archive run URL, toolchain/Qt versions, test logs, tested commits, package digests, screenshots or fixture hashes (non-sensitive), review records and decision deviations. Only after success may status become **ACCEPTED**.

## 13. Deferred decisions

Full UI vocabulary, chart rendering, agent-driven layout, high-frequency sliders, language localisation, multi-window layout, cross-platform packaging and non-Qt renderers are future ADRs or VSLICE-002 expansions. A new ABI or privileged guest world demands a separate architecture decision.

## 14. Concrete implementation profile

The trusted bridge is a dynamically linked Qt Quick/QObject/QProcess frontend and
separate native Rust worker, rather than an untested CXX/FFI library. Kernel and
original bus remain process-local inside that worker. See
[design and review resolutions](../implementation/adr-004/DESIGN.md),
[reproduction](../../apps/desktop-qt/README.md), and
[evidence](../implementation/adr-004/evidence/RESULTS.md).

The canonical schema has a distinct ADR004 ID. Original G0 schema bytes and all
30 original structural fixtures are retained separately as ui-bootstrap; they do
not authorize runtime admission. Existing WIT, component schema, ontology and
ABI/IPC/REG/VSLICE tests remain unchanged. New admission is explicitly opted in,
requires ui.json basename, and rejects ambiguous/nested non-scalar bindings. The
mortgage fixture uses actual calculate/payment ports and a new immutable identity.
All projected display scalar values and counters are exact text on the Qt wire.

The former unresolved storage placeholder is tracked by [ADR-012](ADR-012.md);
no accepted decision history is rewritten. Private adjacent logical snapshots
support tested quit/reopen and save-before-publish but do not settle database
transactions or physical power-cut durability. Cross-platform packaging, platform
screen-reader certification, localization and richer UI remain deferred decisions.
