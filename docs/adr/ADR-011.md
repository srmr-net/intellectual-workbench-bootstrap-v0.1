# ADR-011 — G0 composition, semantic UI and room shape details

**Status:** Proposed — review required; not an approved runtime protocol
**Owner:** SPEC-001 / shared-contract reviewers
**Date:** 2026-10-15

## Context

Architecture §§7,9,12 require schemas but leave widget attributes, binding syntax and reference resolution partly unspecified. The package specification §12 explicitly leaves the UI contract ADR open. SPEC-001 supplies machine-checkable G0 candidates without deciding ABI, Qt, storage, permission scopes or semantic compatibility.

## Proposed decision

Use strict Draft 2020-12 objects, explicit 0.1 versions, exact SemVer/digest pins and unsigned 64-bit revisions. Keep architectural field names and examples. Use dotted ASCII state paths and package-relative UI references. Define recursive containers and closed leaf variants for the minimum control vocabulary. Use declarative button bindings, scalar selector options and property columns for tables. Permission requests use the architecture §11 request shape; scope stays opaque pending ADR-007. Persist no grants. Preserve the existing component manifest schema.

## Alternatives

Free-form UI properties or expression bindings weaken the declarative boundary. Arbitrary URI references would need fetch policy. Adding state migrations or action callbacks now would invent storage/runtime behavior. Defer those features to reviewed versioned contracts instead.

## Evidence / validation

Positive mortgage UI, all-control and permission-request fixtures; negative fixtures cover versions, unknown fields, incomplete pins/endpoints, revisions, expressions, unsafe references and persisted grants. Offline schema checks include reference package JSON and Turtle syntax. See the SPEC-001 task file for exact verification evidence.

## Consequences and trust boundary

No native implementation or trust boundary changes. These schemas do not grant privileges, execute buttons, resolve bindings or prove graph compatibility. Host validation listed in schemas/README.md remains mandatory. Labels are literal display text. Proposals must not be treated as accepted decisions by downstream implementations.

## Compatibility / migrations

Existing manifest and reference sources remain unchanged. New schemas are candidates for SPEC-002; review must settle button semantics, selector/table shape, binding grammar and UI reference resolution before freezing the shared DTOs. Component-state migration versioning remains unresolved under ADR-004; this task retains the documented logical state map rather than inventing state migration metadata.
