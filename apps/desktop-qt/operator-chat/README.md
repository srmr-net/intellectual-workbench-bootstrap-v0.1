# Conversational Operator — Linux Qt prototype

A chat-first entry with real multi-turn OpenRouter conversation. Build `./operator-chat --build`, then run `./operator-chat` (or `./operator-chat --credential-file "$HOME/openrouter.key"`). The supplied private OpenRouter file is used automatically if present and no explicit source/environment credential is configured. Settings enables the provider once per process; only Send initiates inference. Enter sends, Shift+Enter adds a line. Stop cancels; New chat and the sidebar isolate conversations.

The primary view is a scrollable transcript with a bottom composer. The visible transcript remains during this application process; it is **not yet durable across restart**. Each request includes at most the latest twelve successful turns within 48 KiB, plus the new message and fixed host instructions. Failed/cancelled turns and other chats are excluded. Limits: 4 KiB user text, 16 KiB assistant text, 1024 output tokens, 30 seconds, one request at a time, no retries/fallback/tools. Answers arrive as complete messages with asynchronous progress; token streaming is not implemented.

The fixed route is OpenRouter `/api/v1/chat/completions`, `nvidia/nemotron-3-ultra-550b-a55b:free`, NVIDIA only, zero-price filters. Settings discloses recent-history transmission and NVIDIA logging. Credentials are loaded by the native host using the accepted credential policy. No prompt/response body is written to diagnostic logs or room snapshots. Model text is inert plain text with external links disabled.

Settings → Tools opens the existing component workspace through its fixed trusted launcher. Chat cannot run components, inspect the registry, execute commands, read files or bypass proposal-bound approval. No component-runtime code or accepted schemas are modified. The native chat worker has no registry/kernel handle and compiles the accepted `live-provider/host/src/{policy,transport}.rs` sources directly without changing them.

Host API: `chat.1`, strict length-prefixed JSON over stdin/stdout; operations and policy in [ADR016](../../../docs/adr/ADR-016.md). This is a new conversation protocol, **not** an extension of the accepted suggestion ABI. Worker frames are bounded; malformed frames terminate the connection. Qt discards cancelled/superseded request generations. Closing drops and reaps active transport. `--fixture` is an explicit offline test mode using a separately built feature-gated binary and is visibly labelled.

Status: Proposed; see [task](../../../docs/implementation/operator-chat/TASK.md). Deterministic native and Qt evidence, independent reviews and live validation are recorded separately. No production acceptance or autonomous agent capability is implied.

Native transcript limits reserve escaped JSON space before requesting another answer (under 1 MB per selected transcript, at most 198 messages); 16 conversations and 256 sends are allowed per application process. Reconfiguration revokes/cancels first, even if the replacement credential path is invalid. Switching/new chat stops the pending answer. The composer is briefly read-only during control transitions, remains editable while the model thinks, and preserves drafts separately by chat.

Official API references checked for this implementation: [OpenRouter chat API](https://openrouter.ai/docs/api/reference/overview), [provider routing](https://openrouter.ai/docs/features/provider-routing), and the [selected NVIDIA model](https://openrouter.ai/nvidia/nemotron-3-ultra-550b-a55b:free). Provider availability and exact served version are observations, not guarantees; only returned metadata may establish them for a particular live call.
