# ADR-001 guests and reproduction

This is a separate, locked Cargo workspace, excluded from the native workspace.
Each guest is compiled in its own `cargo component build -p ...` invocation.
Both positive guests use `wasm32-unknown-unknown`: `echo` transforms JSON text to
uppercase; `integer` doubles a signed 64-bit integer with checked overflow.
Neither requires host imports. `denied-wasi` intentionally targets `wasm32-wasip1`
and calls `std::fs`; its compiled filesystem imports are rejected before execution.
Echo command strings select error/trap/loop/memory/oversize modes for regressions;
these are test behavior, not Workbench capabilities.

Prerequisites on Linux: C toolchain, OpenSSL development headers/pkg-config,
Python with `tools/requirements.txt`, Rust **1.99.1** with rustfmt/clippy and both
WASM targets, **cargo-component 0.21.1**. For example:

```sh
rustup toolchain install 1.99.1 --profile minimal --component rustfmt --component clippy --target wasm32-unknown-unknown --target wasm32-wasip1
cargo install cargo-component --version 0.21.1 --locked
python3 -m venv /tmp/workbench-abi-python
/tmp/workbench-abi-python/bin/pip install -r tools/requirements.txt
# Put the temporary Python environment and cargo-component's bin directory on PATH.
cargo component --version
cargo component --help
cargo component build --help
bash examples/wasm-components/validate.sh
```

`build.sh` enforces the cargo-component version, builds all guests with `--locked`
and generates ABI-only manifest JSON with raw binary hashes. Native host imports
no WASI implementation. Guest metadata points at the single `wit/` directory;
`src/bindings.rs` files are generated and ignored, never maintained copies of WIT.
Cargo.lock files pin native/guest dependencies. The component resolver has only
local WIT dependencies; no Component.lock is generated by this tool for this case.
Cargo 1.99 prints `cargo-component-component 0.21.1`; the version guard accepts
this upstream CLI naming quirk while checking the exact version number.

Artifacts live under `target/abi-guests/`; ABI-only manifests under
`target/abi-fixtures/` and logs/hashes under `target/abi-evidence/`. The manifests
are **not installable packages**: RDF/package-install conformance is outside this
spike. Nothing changes the metadata-only mortgage example.

`validate.sh` builds first, records versions/dependency tree and SHA-256, executes
the entire Rust workspace/ABI tests, Clippy and Python contract/harness checks,
then runs the required whole-workspace formatting check. It fails on any failing
check and preserves logs, including the known baseline formatting failures.
Linux CI uploads that evidence even on failure. After every check passes,
`collect_evidence.py` archives the exact lockfiles, WIT and guest binaries with
`run.json` recording the tested Git SHA, versions, check outcomes and hashes.
The same metadata appears in the GitHub job summary; it contains only explicit
non-secret environment fields. For only the ABI suite after
building: `cargo test --locked -p wb-wasm-host --test abi -- --nocapture`.

Official CLI/build documentation consulted:
[Bytecode Alliance cargo-component](https://github.com/bytecodealliance/cargo-component)
and [Wasmtime 49.0.1 embedding API](https://docs.rs/wasmtime/49.0.1/wasmtime/).
Results and acceptance limitations are in
`docs/adr/evidence/ADR-001-results.md`; no hosted CI or other-platform success is
implied by the local Linux run.


ADR-002 adds a separate `ipc-aggregate` guest and `validate-ipc.sh` wrapper. The
wrapper retains every ABI check and adds native kernel/bus/reactive conformance.
The fourth guest uses the accepted WIT without imports, computes checked integer
value+add from one aggregate input, and supplies adversarial error/batch/provenance
modes for tests. Existing guest sources are unchanged. The collector now archives
that binary too, records all ten ABI and fifteen IPC case IDs, and writes
`ipc-report.json`; local declaration checks do not claim hosted success. Hosted
workflow artifacts are named `ipc-validation-linux` and include original ABI logs.
